# Разметка именованных сущностей (персоны) в корпусе Tolstoy Digital

# 1\. Исходные данные: справочник персон

1. Используется TEI-справочник: listPerson  
2. (текущая версия: [https://github.com/tolstoydigital/TEI/blob/master/reference/personList.xml](https://github.com/tolstoydigital/TEI/blob/master/reference/personList.xml))  
3. Для каждой персоны заданы:  
   1. уникальный ID  
   2. ФИО (в процессе декомпозиции на составные части)  
   3. возможные варианты имен (альтернативные написания, формы, иногда прозвища)  
4. Новая, более подробная версия справочника находится в разработке, структура изменится, но относительная преемственность сохранится.  
5. Важно: система должна уметь работать не только с полным именем, но и с:  
   1. отдельными компонентами (имя, фамилия)  
   2. вариантами написания  
   3. частичными совпадениями

# 2\. Корпус текстов

Все тексты существуют в двух версиях:

1. TEI (основная для работы)  
2. HTML (front, производная; генерируется автоматически)

Работа ведется только с TEI-версиями.

#### 2.1. Тексты Толстого и комментарии

#### 2.2. Тексты окружения Толстого

# 3\. Разметка в текстах Толстого и комментариях

1. Требуется разметить каждое упоминание персоны в тексте.  
2. Формат: TEI-разметка с привязкой к listPerson (через ID).  
3. При повторных упоминаниях:  
   1. возможно использование дополнительного атрибута (например, rend="hidden"),  
      чтобы не перегружать интерфейс повторяющимися справками.  
4. В перспективе: логика отображения (что показывать пользователю) отделяется от факта разметки.

# 4\. Разметка в текстах окружения (tolstoy-bio)

1. Не требуется размечать все вхождения в тексте.  
2. Достаточно:  
   1. зафиксировать факт однократного (или более частого) упоминания персоны в документе.  
3. Результат:  
   1. добавление связей в метаданные документа  
      (файл: [https://github.com/tolstoydigital/TEI/blob/master/reference/bibllist\_bio.xml](https://github.com/tolstoydigital/TEI/blob/master/reference/bibllist_bio.xml))  
4. Практическая реализация:  
   1. предпочтительно формировать CSV для импорта в БД  
   2. затем синхронизация с bibllist\_bio.xml

# 5\. Текущее состояние разметки

1. Часть разметки уже выполнена:  
   1. размечены наиболее значимые (высоковесные) упоминания  
2. Новая система должна:  
   1. учитывать существующую разметку  
   2. проверять ее  
   3. не перезаписывать ее некорректно  
   4. уметь доразмечать тексты

# 6\. Дополнительные данные (для текстов Толстого)

1. Имеются сведения из именных указателей: тома и страницы (данные о них храним в большинстве документов), на которых упомянуты персоны  
2. Эти данные могут использоваться:  
   1. для валидации  
   2. для повышения точности автоматической разметки

# 7\. Цель: автоматизация, контроль качества и обогащение данных

Задача — не просто автоматическая разметка, а создание полуавтоматической системы, включающей несколько уровней:

## 7.1. Автоматическое распознавание и разметка

1. Поиск упоминаний персон в тексте на основе:  
   1. словаря (listPerson)  
   2. вариантов имен  
   3. контекстных эвристик (например, инициалы \+ фамилия)  
2. Разрешение неоднозначностей:  
   1. выбор правильного ID при совпадении фамилий  
   2. учет контекста (эпоха, окружение, текст)

## 7.2. Система весов упоминаний

Необходимо разработать модель «веса» упоминания, которая может учитывать:

1. степень совпадения имени в тексте и имени из словаря  
2. наличие в указателях (том/страница)

Возможные применения:

1. приоритизация для проверки  
2. управление отображением (что показывать пользователю)  
3. фильтрация «шумовых» упоминаний

## 7.3. Автоматическая проверка 

Нужна система валидации разметки:

1. поиск пропущенных сущностей (на основе словаря)  
2. выявление:  
   1. неверных привязок к ID  
   2. дублирующих или конфликтующих разметок  
3. контроль консистентности:  
   1. одинаковые сущности размечены одинаково  
   2. нет «разрывов» (часть упоминаний размечена, часть — нет; размечена только часть имени, представленная в тексте)

## 7.4. Работа с существующей разметкой

Система должна:

1. распознавать уже размеченные сущности  
2. не дублировать их  
3. при необходимости:  
   1. уточнять  
   2. нормализовать  
   3. дополнять атрибутами

## 7.5. Генерация производных данных

Для текстов окружения:

1. автоматическое формирование списка упомянутых персон по документам  
2. экспорт в CSV для импорта в БД

## 7.6. Использование LLM / агентов

Настройка агентов, которые смогут:

1. выполнять разметку  
2. предлагать варианты привязки к listPerson  
3. учитывать контекст  
4. определять степень уверенности в решении  
5. выявлять сомнительные случаи  
6. объяснять свои решения (для проверки)
